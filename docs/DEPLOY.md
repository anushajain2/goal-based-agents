# Deploying Autopilot on Render

Everything is described in [`render.yaml`](../render.yaml) (a Render "Blueprint"). Render reads it
and creates the whole setup. You don't need to run any servers yourself.

```
            people
              │  https://app.yourdomain.com
              ▼
   ┌───────────────────┐   private network   ┌───────────────────┐
   │  autopilot-web    │ ──── /api/* ──────▶ │  autopilot-api    │
   │  Next.js          │                     │  FastAPI (Docker) │
   └───────────────────┘                     └─────────┬─────────┘
                                                       │
   ┌───────────────────┐                     ┌─────────▼─────────┐
   │  autopilot-worker │ ◀──── Postgres ───▶ │  autopilot-db     │
   │  AI employees 24/7│    (queue + live    │  managed Postgres │
   └───────────────────┘     updates)        └───────────────────┘
```

| Piece | What it does | Plan in render.yaml |
|---|---|---|
| autopilot-web | The app people open. Sends `/api/*` to the API over Render's private network, so everything is one address and cookies just work. | Starter |
| autopilot-api | Sign-in, goals, approvals, live updates. Runs database migrations before each deploy. | Starter |
| autopilot-worker | Runs AI employees, company setups and team-lead reviews around the clock. On a deploy it finishes or hands back its work, so nothing is lost. | Starter |
| autopilot-db | Postgres with daily backups. Only the services above can reach it. | Basic 256 MB |

All of it runs in Frankfurt. To use another region, change `region:` everywhere in `render.yaml`, keeping
all four in the same region. Check current prices on render.com/pricing. Four small instances cost
roughly a few dollars each per month. Claude usage is billed separately by Anthropic.

## One-time setup (about 30 minutes)

### 1. Create the services

1. Sign up at render.com with your GitHub account, and allow it access to this repository.
2. In the dashboard, choose **New → Blueprint**, pick this repository and the `main` branch.
3. Render lists the four resources and asks for the values marked `sync: false`. Fill in:
   - `FRONTEND_ORIGIN`: the address people will open. If you already have a domain, use
     `https://app.yourdomain.com` (step 2). If not, the app's Render address doesn't exist yet, because
     Render creates `autopilot-web` only after the API is up. Put in a placeholder like
     `https://example.com`, then replace it with the `autopilot-web` URL
     (`https://autopilot-web-xxxx.onrender.com`) once that service appears. Until it's replaced,
     sign-in won't work. Leaving it empty stops the API from starting
     (`config error: FRONTEND_ORIGIN ...` in its logs).
   - `ANTHROPIC_API_KEY`: required.
   - `SMTP_*`: required for real users, because sign-in codes go by email (see step 3).
   - Leave anything you don't have yet empty. Every optional feature switches itself off without
     its key, and you can add keys any time under **Environment Groups → autopilot-backend**.
     Saving restarts the services.
4. Click **Apply**. The first build takes about 5–10 minutes. `autopilot-api` runs
   `alembic upgrade head` before it starts; the worker waits for that.

`SECRET_KEY` is generated by Render. Don't change it: changing it signs everyone out.

### 2. Your domain (optional, recommended)

In **autopilot-web → Settings → Custom Domains**, add `app.yourdomain.com`. At your DNS provider, add
the `CNAME` record Render shows. Render issues the HTTPS certificate itself. Then set
`FRONTEND_ORIGIN` to `https://app.yourdomain.com` in the environment group.

The API doesn't need its own domain, because the app reaches it privately. When the desktop helper
arrives, it will connect to `api.yourdomain.com`, and you'll add that domain on `autopilot-api`.

### 3. Email for sign-in codes and invites

Any SMTP service works. With [Resend](https://resend.com) (or Postmark):

1. Add and verify `yourdomain.com` (they give you DNS records for SPF/DKIM).
2. Create an SMTP credential and set:
   `SMTP_HOST=smtp.resend.com`, `SMTP_PORT=587`, `SMTP_USER=resend`,
   `SMTP_PASSWORD=<the API key>`, `SMTP_FROM=Autopilot <login@yourdomain.com>`.

Without SMTP, codes only appear in the `autopilot-api` logs. That's fine for a quick private test,
not for anyone else.

### 4. Sign in with Google / GitHub (optional)

The callback URLs are on your `FRONTEND_ORIGIN`:

- Google (Cloud Console → Credentials → OAuth client, Web application), authorised redirect URI:
  `https://app.yourdomain.com/api/auth/google/callback`
- GitHub (github.com/settings/developers → OAuth app), callback URL:
  `https://app.yourdomain.com/api/integrations/github/callback`

Put the IDs and secrets in the environment group.

### 5. Protect your Claude bill

In the Anthropic console, set a monthly **spend limit** on the key you use here. Each goal also has
its own budget in Autopilot, but the console limit is your backstop.

### 6. Error reports (optional)

Create a Sentry project (Python) and set `SENTRY_DSN`. The API and the worker report crashes. No
personal data is sent.

## Every day after that

- **Deploying**: push to `main`. GitHub Actions (`.github/workflows/ci.yml`) runs the backend tests,
  the migration check, the frontend build and the Docker build. Render deploys only once they pass.
  Changes under `frontend/` redeploy only the app; changes under `backend/` redeploy the API and worker.
- **Logs**: each service has a Logs tab. Look in `autopilot-worker` for what the AI employees are doing.
- **Rollback**: on a service, choose **Deploys → Rollback** next to an earlier deploy. Database
  migrations are not rolled back. They're written to be compatible with the previous version.
- **Backups**: under `autopilot-db → Recovery`.
- **More capacity**: raise `AUTOPILOT_MAX_CONCURRENT_RUNS` on the worker, or add instances (Scaling).
  Workers share the queue safely, so any number can run side by side.

## A staging copy (optional)

To try changes before customers see them, create a second Blueprint from the same repository, on a
`staging` branch. In the dashboard, rename the resources with a `-staging` suffix when Render shows
them. Or, if the New Blueprint screen lets you choose the file path, copy `render.yaml` to
`render.staging.yaml` with renamed services and pick that file. Use a separate Anthropic key with a
low spend limit.

## What's different from running it on your computer

- **No Agent Chrome.** A server has no screen and nobody to sign in to sites, so `AGENT_CHROME=false`.
  AI employees work through connected apps (Composio, MCP, GitHub, databases) and web research.
  A step that needs a website with no connector is asked about or left for the desktop helper. The
  Connections page says so.
- **Private network MCP servers are blocked** (`ALLOW_PRIVATE_MCP=false`), so nobody can point Autopilot at
  Render's internal machines.
- **Production checks.** With `ENVIRONMENT=production`, the API and worker refuse to start without a
  `SECRET_KEY`, a Postgres `DATABASE_URL` and an `https://` `FRONTEND_ORIGIN`. Missing email or Claude
  keys are logged as warnings.

## Trying the production image locally

```bash
docker build -t autopilot-backend backend
docker run --rm -p 8000:8000 -e ENVIRONMENT=development autopilot-backend
curl localhost:8000/api/health
```
